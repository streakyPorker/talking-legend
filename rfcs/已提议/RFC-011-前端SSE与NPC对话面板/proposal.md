# RFC-011: 前端 SSE 与 NPC 对话面板

> **状态**: 已提议
> **优先级**: P2
> **创建**: 2026-07-26

## 问题

后端 005/006 将提供 SSE 流式叙事与 NPC 对话能力，但前端目前只有一次性 fetch 的 `services/api.ts`，完全没有流式接收与分区展示能力。

核心痛点：

1. **流式体验是核心卖点**：GM 叙事逐字涌现 vs 转圈十秒后整段砸下来，是两种游戏——设计决策明确双 SSE 连接、分区独立即时展示
2. **NPC 对话无界面**：与同区域 NPC 对话需要独立面板（对话历史、NPC 状态、情绪展示），当前 UI 完全不存在
3. **输入锁定交互**：GM 生成期间禁用输入框、done 事件后解锁，需要前端状态机配合
4. **断流与异常**：SSE 断线、LLM 降级兜底文案的 UI 呈现都需要设计

## 动机

这是玩家直接感知的最后一公里：后端 LLM 能力通过 SSE 与对话面板变成体验。依赖 010 的组件化基础。
