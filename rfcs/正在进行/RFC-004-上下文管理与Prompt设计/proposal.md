# RFC-004: 上下文管理与 Prompt 设计

> **状态**: 已提议
> **优先级**: P1
> **创建**: 2026-07-26

## 问题

项目核心玩法由 LLM 驱动，但目前没有任何 prompt 与上下文管理的工程化设计：

1. **上下文来源分散**：游戏状态散落在 8 张表里（世界、NPC、记忆、任务、事件链），每次 LLM 调用需要决定取哪些、取多少、如何组织——没有统一方案
2. **token 成本与效果矛盾**：全量上下文昂贵且稀释关键信息，过少上下文又让 GM/NPC「失忆」；NPC 记忆会随游戏推进无限增长，必须有过滤与压缩策略
3. **三层模型各有诉求**：Opus（GM 叙事）、Sonnet（NPC 对话）、Haiku（意图分类/记忆过滤）的 prompt 结构、上下文窗口、输出格式要求完全不同
4. **无契约易腐化**：没有 prompt 模板与上下文组装的明确边界，后续每个 LLM 接入点都会各写各的，迅速腐化

## 动机

这是 LLM 接入三件套（005/006/007）的共同前置。设计决策已定调「先敲定一版方案，实现后边测边调」——本 RFC 负责敲定那一版方案：上下文组装管线、prompt 模板结构、记忆过滤策略。
