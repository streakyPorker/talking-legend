# RFC-005: LLM 接入 — GM 引擎与 SSE

> **状态**: 已完成
> **优先级**: P1
> **创建**: 2026-07-26

## 问题

GM（Game Master）叙事是核心玩法 loop 的主干，但目前是占位实现：`GameService.performAction()` 返回固定模板字符串（"You look around. The world shifts subtly in response."），不调用任何 LLM。

核心痛点：

1. **玩法不成立**：没有真实叙事生成，游戏只是一个能转 turn 的状态机
2. **同步等待不可接受**：Opus 级模型生成一段叙事需要数秒到十几秒，同步 HTTP 会让用户面对死等的输入框——需要流式输出
3. **LLM 与事务冲突**：RFC-002 已定 `db.transaction()` 回调内禁止 async 操作，LLM 调用必须采用两阶段模式（事务内读 → 事务外调用 LLM → 事务内写回），这是首次落地该模式
4. **生成期间的状态一致性**：GM 生成期间玩家不应能继续提交动作，需要输入锁定与并发互斥

## 动机

这是第一个真实 LLM 接入点，会确立后续所有 LLM 调用的工程范式：流式 SSE 协议、两阶段事务、调用日志（llm_logs 表已就绪）、降级兜底。设计决策：GM 叙事走 Opus，前端在生成期间锁定输入直到 done 事件。
